# Architecture

Each rule here guards against lost sessions, misdelivered input, or leaked data. Build and test mechanics are in the [README](../README.md#quick-start) and [test/README.md](../test/README.md); tmux, herdr, SSH, and agent lifecycles are in [integrations](integrations.md).

| Owner | Owns |
| --- | --- |
| [AppDelegate](../Dispatch/AppDelegate.swift) | Wiring, restoration, shutdown order. |
| [Workspace](../Dispatch/Workspace.swift) | Spaces, panes, tabs, selection, host placement. Related mutations publish together through `updateLayout`. |
| [TerminalRuntime](../Dispatch/Terminal/TerminalRuntime.swift) | The terminal engine and its surfaces, keyed by stable UUID. |
| [Hosts](../Dispatch/Hosts/) | Presentation identity, kept separate from live process ownership and connection recipes. |
| [SSH](../Dispatch/SSH/) | Enhanced-connection authentication and per-connection feature grants. |
| [Helper](../Dispatch/Helper/) / [Herdr](../Dispatch/Herdr/), over the helper's [tmux](../helper/multiplexers/tmux/) and [herdr](../helper/multiplexers/herdr/) crates | Mapping server-owned sessions into native spaces and tabs. |
| [Chat](../Dispatch/Chat/) | Agent discovery, per-surface sessions, drafts, submissions, approvals. |
| [Views](../Dispatch/Views/) | Presentation only. Views never own shell lifetime. |

The Mac and iOS apps compile common model, parsing and protocol cores from `Dispatch/`; `project-mobile.yml` (the
iPhone and Watch apps' own Xcode project, `DispatchMobile.xcodeproj`) lists the phone's shared files explicitly.
Native presentation, connection generations and process ownership remain with each app.
[Shared sources](ios.md#shared-sources) describes the boundaries; portable regression cases compile in both test
targets. Terminal rendering/configuration work shared by the native adapters lives in `TermApple`.

## Invariants

- **Threading.** Workspace and UI coordinators are `@MainActor`. Blocking I/O, process inspection, and heavy parsing run on transport actors or background workers that report back to the owning coordinator.
- **Identity.** Host changes, reorders, splits, and Terminal↔Chat switches preserve surface and conversation identity. Presentation changes never relaunch a shell or acquire input authority.
- **Layouts.** The presets (`LayoutPreset`: single, two columns or rows, two above one, 2 × 2, 3 × 2 and 4 × 2; ⌃1…4, ⌃6 and ⌃8 by default, the View menu, the layout picker) move existing tabs into panes and never start a shell; their dividers share each axis evenly (`PaneLayout.evenFractions`, a third for three across). A preset places by where panes show (`LayoutPreset.arrange`): each pane goes into the new pane it overlaps most, the focused one first, or joins the one it overlaps most once none it overlaps is free (a grid's top right joins the top row, never the bottom); joined panes keep their reading order and their tabs'; a pane left empty takes the last hidden tab of the pane that covered its place, the last in reading order first, so tabs split off in runs and join back in order. Each space remembers what every preset held when it was last left (`LayoutMemory`, kept with the space, by tab or a server's window): choosing it again puts each tab back in its pane, in its order, each pane showing what it showed, with the dividers where they were (rows → grid → rows changes nothing); tabs new since go where the placement puts them, and a tab the user moved to another pane in between is forgotten, so it stays where it was put. Choosing the layout already shown evens its dividers. ⌘D and ⇧⌘D (Split Right, Split Down; tmux's `split-window` prefix keys too) always split as iTerm and Ghostty do: a new tab in the focused tab's folder, in a new pane beside the focused one, again on every press up to four panes (`Workspace.splitPane`); in a tmux or herdr space the new tab is a server window shown beside the focused one. View › Merge Panes, which has no key, joins the innermost split around the focused pane into one pane with all their tabs and focus unchanged (`Workspace.mergeSplit`). With split panes, ⌘1…9 focus the panes in reading order; without, ⌘1…8 select the first eight tabs and ⌘9 the last, as in Safari and Terminal (`Space.tabShortcutNumber`: past nine tabs the ninth shows no number and the last shows 9). Each layout has one title-case name everywhere, the View menu, the picker, the ⌘/ sheet and Settings (`LayoutPreset.title`: Single, Side by Side, Stacked, Two Above One, Grid, Grid of Six, Grid of Eight), and a layout key that cannot apply beeps and says why in a note over the window (`Workspace.layoutRefusal`, `WindowNotes`: "Grid needs 4 tabs. This space has 2."). Six and eight panes need room: each pane at least 60 × 24 cells of the terminal font inside its padding (`LayoutPreset.fits`), against the window's pane area that `MainView` measures into `Workspace.layoutRoom` (view state, never saved) on every resize, font change and screen change. A display connected or disconnected is only that: the window moves and resizes, and nothing listens for displays. The picker and the View menu hide a large layout that would not fit even with the window filling its screen (a laptop never lists them) and disable one that fits the screen but not the window; the space's own layout always keeps its row. A layout already applied never changes when its room shrinks (a display unplugged, a dock or KVM waking, a relaunch on a smaller screen): its panes get smaller until the user picks another. Up to four panes ignore the room.
- **Vertical tabs.** Settings › General › Tabs & spaces › Vertical tabs (`Preferences.verticalTabs`, stored under the `tabsOnly` key of the mode it replaced, so a choice made there carries over) is presentation only: spaces, panes, tabs, layouts and backends are what they are with strips, and every command (⌘T, ⌘D, ⌘1…9, ⌘[ / ⌘]) acts as it does there. The sidebar goes into the shown space (`SpaceTabsList`, mockups/Mac U1–U10): a bar with the sidebar toggle, then New Tab, ending where the rows' shortcuts do, every control one glass circle's size; the space's heading (Back, a glass circle with the count of other spaces waiting on you, centered before the name; the name, which opens the space menu; dimmed the host and the folder, or a tmux or herdr session's git branch; and with two tabs or more the layout picker, the circles' size, centered under New Tab (the host's widget is the footer's); over a rule; the space menu has Rename, then Detach and Terminate, or Close for a native space; other spaces are Back's); its tabs, a row each in its panes' reading order (its close button under the pointer, in the activity's place), under a heading per pane while the space is split, or per window group while a server's windows are split side by side (led by the layout with that pane filled, its place, "Left" or "Top right", or "Pane 3" for every pane when two places would read the same, as four across have two middles, and its ⌘ digit; the tabs then show none); a tmux or herdr window's panes a line each under its row (a line's click focuses that pane). Large draws each tab as a card (`SidebarCardChrome`, as a space's): its kind on a neutral orb, the status's glyph in its place while the tab has news other than work. Showing a space goes into it (`Workspace.selectSpace` clears `sidebarListsSpaces`, view state, never saved; the tabs push in 60 points from the trailing edge as the spaces leave by the leading one, and Back the reverse, fading over 0.16 s with the bars crossfading, none with Reduce Motion: `SpaceSidebar.push`); Back and a search list the spaces under a header row of icons only (no Spaces ⌄ menu): the sidebar toggle and the tree toggle, then the shortcuts and, in tree order, New Space (`NewSpaceButton`, right-click for a host; a host's heading under the pointer also shows a + before its mark, which makes a space on that host and lists its backends on a right-click: `SpaceSidebar.headingPlus`, hover from an AppKit tracking area, `PointerTracker`, since the heading's AppKit controls hide it from SwiftUI's onHover), the bar's New Tab's circle in its place, each host's mark (`HostHeadingMark`: its icon dimmed, on a disc under the pointer, so New Space is the one raised circle; it opens the host's widget) centered under it; flat order has "+ space" under its list instead, with "+ local" while a remote host is connected (`NewSpaceListButton`). No pane has a strip (nor a server window's panes their headers): the content takes the window's full height, each pane's mode switch floats at its top-right corner (with the sidebar hidden, the top-right pane's with the layout picker beside it, `TerminalContentView.floatingLayout`; in Chat only on the focused pane; in Files at the end of the Files header, `filesHeaderAccessory`, so it never covers the header), and with the sidebar hidden the sidebar toggle floats beside the traffic lights (`MainView.floatingSidebarToggle`). With the sidebar hidden, the host mark's space picker (`StripSpacePicker`, full screen's way to the spaces) lists the shown space's tabs under its row (`StripPickerTabRow`: activity, kind, title, ⌘ digit, the focused one checked) and offers New Tab, there being no strip to reach them. With one space the sidebar hides only while that space has one tab.
- **Automatic tab names** (`TerminalTab.displayLabel`, `ContainerTab.displayLabel`; the phone's `MobileTab.label` uses the same `TerminalTab` rules) follow what Files shows while the tab shows it (`FilesTab.tabName`, both apps: Files the open file with its folder, `auth/token.ts` or `~/notes.md`, else the folder browsed; Review "Review" and the branch; Commits the open commit's subject, shortened to 48 characters, else "Commits" and the branch), else the agent's conversation title, then the program's own title or the multiplexer's name, then the folder at a prompt. A numbered tab takes its focused pane's title unless it names the folder or repeats the tab's name, else the folder, else the tab's name (`paneLabel`). The typed launcher's name (`dispatch-helper launch claude` on an SSH host: tmux names the window after it, the helper's own terminals after its path) shows as the tab's agent (`shown`): the key Chat bound, else the one the topology's binding names (`agent(named:)`, from the executable, the pane's and the window's names), so it shows before Chat binds and with Chat off.
- **Server-owned sessions.** Detaching a native view from tmux/herdr is not terminating server work. Backend snapshots reconcile existing presentation identities in place.
- **Remote trust.** A host is one login, a machine and the account on it, as on the iPhone: aliases of one account group, two accounts on one machine are two hosts sharing the machine's color and each named `account@host`. Grouping is presentation, not a permission boundary: grouped aliases can have different grants. Remote operations carry authenticated connection/process identities and generations, and a remote PID is never a local PID. Agent hooks on a remote connection need that connection's grant. Ordinary SSH works without the helper.
- **Screens.** The Mac never publishes screens (`terminals.publish`) for the tmux and herdr terminals of a helper whose hello accepted `screens.host`: that helper reads them from the multiplexer, and one publication would turn its host reads off for that terminal. It publishes native terminals and SSH logins a helper observes in a tab, and everything to a helper without the feature (`HelperWorkspace.publishes`); a terminal that publishes to nobody reads no screen until that changes (`TerminalView.wakeScreens`).
- **Hidden terminals.** A hidden terminal's output is held on the host, never dropped silently: showing it again restores the screen. A chat tab whose terminal is not on screen may stop its subscription's output (`terminals.follow` false, helpers that accepted the feature, tmux and herdr only); following again gets that subscription alone a whole repaint before any later output, and input, exits, chat records and the host's screen reads go on meanwhile. Plain terminal tabs always follow. While output to the app is backed up the helper still reads and runs its requests (`requests.backlog`: keystrokes, cancels, `terminals.follow false`, pings; up to 256 waiting replies or 1 MiB), so a flood in a visible pane delays only the replies, not what the requests do. An output window (`terminals.window`: at most 256 KiB of unacknowledged terminal output per client, acknowledged per attach subscription by `HelperOutputWindow` once handed to the terminal (batched while streaming, flushed when quiet), the multiplexers paused past it) exists but is off by default (`HelperSession.outputWindow`; the "Slow connection mode" setting turns it on for new connections). Before turning it on by default, move the acker's flush timer (a `DispatchQueue` delay today) onto `System` timing so recorded tests can enable it, and measure again over a shaped link ([benchmarks](benchmarks.md#ssh-over-a-slow-or-lossy-link)).
- **Hidden terminals' GPU memory.** A terminal whose tab is not shown (another tab or space, whose view leaves the window, or Chat/Files covering it) keeps its process, screen and history but gives back its drawing memory 5 s after it was first reported hidden (`HiddenResources.retention`; repeated reports do not restart it): the swap chain's IOSurfaces and the layer's frame, the renderer's buffers, atlas and image textures; quicker switches keep them. Showing it again draws a frame synchronously before the view appears (one the GPU finishes late is shown when it does), so no empty frame shows. A terminal that is shown in its tab but whose window is covered or minimized releases only on memory pressure, and then keeps its last frame as the layer's contents, since the window server can show it again before the app hears it is visible. Every hidden terminal releases at once on a memory pressure warning. The phone releases its renderer's buffers and textures the same way (its layer keeps the last frame). Terminals on one GPU share the shader library and pipelines (`MetalRenderer.pipelines`).
- **History memory.** Page blocks no page uses (cleared or reflowed history in a page list's pool, a closed terminal's in `SharedPageBlocks`) are marked `MADV_FREE_REUSABLE` (`PageBlockMemory`) until a page takes one again, which zeroes what it uses: the system may reclaim them and the footprint does not count them. Scrollback in use is not compressed (Ghostty 1.4 compresses idle pages; measured, history pages compress to 2–4% with LZ4, a candidate once the page store's access paths are settled).
- **Off-screen chats.** While a chat's main window is off screen (ordered out, or the app hidden; not minimized), its transcript keeps the rows it showed when the window left (`ChatSession.holdTranscript`): records, unread state, approvals and notifications go on in the model, but no row is laid out or mounted for them. `MainWindow` posts `willShow` before it is ordered in or its app unhides; the transcript applies what it held there, and the window lays it out, draws and commits it before it is ordered in, so no stale frame shows. A covered (occluded) window keeps updating: the window server shows it again before the app hears it is visible.
- **Chat layout and scrolling.** The Mac transcript uses an AppKit scroll view and an owned virtualized document (`ChatTranscriptScrollView`), with the existing SwiftUI message views hosted per row. The document owns row frames, cached heights and clip positioning through one layout entry point (`layoutTranscript`), which does nothing unless the clip moved, the controller's positioning inputs changed or something was invalidated. A pass builds and measures every row the presented clip intersects (once, from its root's ideal height without a layout flush, so a row is laid out only at its measured size), places them and restores either the latest output or a message ID plus pixel offset before drawing. Each chat's `ChatScrollPosition` (`ChatSession.scrollPosition`) holds the one positioning intent the document realizes on every layout: the latest output, a message held at a pixel offset (a reopened view, a find, a prepend) until a layout mounts it, or nothing, which leaves the reader's message where it is or follows the bottom while the view does. It turns wheel, key and scrollbar input into giving up that intent, prefetches earlier history near the top, draws the overlay scrollbar (which fades 1.2 s after the last scroll through one pending timer whose deadline each wheel event moves, not a wake-up per event, and whose hidden thumb takes the clip's position only when it shows, so streaming and programmatic movement redraw nothing) and holds the rows while the window is off screen; it computes no row geometry and moves the clip itself only for the arrival glide. The lookahead, a viewport in the direction of travel (up to three while scrolling fast: 0.25 s of travel) and a quarter behind, is built in run-loop turns of its own after the turn that scrolled, within a 3 ms budget (one row); a document that just entered a window (a tab switched to) starts it only after 0.3 s or once the clip moves, so switching through tabs builds only what each one shows. It also measures again a lookahead row whose content changed size after it was measured (asynchronous tool output), so the row has its final height before it enters the clip; while the reader scrolls, a pass does not anchor on a row cut off by the clip's top that still waits for that, so its growth goes above the reader; at rest that row keeps its offset and grows downward (it may be a disclosure the reader just clicked). The representable takes the size SwiftUI proposes (its parent `GeometryReader` always proposes one) instead of AppKit's `fittingSize`, which would build a temporary constraint engine over every hosted row on each layout of the enclosing view. Hosts leaving the lookahead are hidden and kept for a reversal, within 1.5 viewports of total height, 16 hosts and 3 viewports from the clip; a hidden host takes no hits, is no anchor and does not count as mounted (`mountedRows`, which diagnostics and `showsRows` read), and is released after 1.5 s without movement, when its row leaves the transcript or when the width changes. A host keeps its SwiftUI root while its row's `ChatTranscriptRowRevision` (revision IDs and flags of what the row closure captures by value) and the shared context are unchanged; what a row observes updates in place. Offscreen height estimates never position already-visible content independently, and an elastic overscroll past either edge is left for AppKit to return, while rows changing above the reader still correct it. Following settles 22 points above AppKit's own bottom edge, and a followed clip below that offset that AppKit moved within the last 0.5 s (a momentum scroll, or a bounce returning to AppKit's edge) is left alone too, moving only further down for new content; a clip the passes left there, because rows above it measured shorter than their estimates (the lookahead after a chat appears), goes to the follow offset in the same pass, or the text would drop 22 points for a frame or two: pulling it back on each frame fought AppKit's animation, which then never ended and flung the clip far past the document. During AppKit's live scroll (a gesture, its momentum or bounce, between its live-scroll notifications) following does not move the clip at all, even after momentum near the bottom arms it again: AppKit applies its own origin on every frame, so any correction there starts that fight. The live scroll's end lays out once and settles a followed bottom. Short followed arrivals glide (0.22 s, one step per displayed frame, at the motion policy's rate: 60 on battery); larger bursts pin directly to keep row construction bounded. While the reader reads earlier rows (not following) and the conversation's end is more than two viewports below, records that only change that end reach the transcript's views at most every 0.25 s (`ChatSession.TranscriptHold.reading`, the off-screen window's hold): each record would otherwise rebuild every row's list and revision for rows nobody sees; a disclosure, an approval, a turn's start or end, earlier history, a scroll or following again presents at once, and it is off while testing (`ChatSession.readingHoldEnabled`), as the typed reveal is. Content, bounds, scrolling and visibility changes invalidate layout, and every host checks its ideal height after each of its own layouts, so content that grows on its own (formatting arriving, an observed model changing) is measured again without a per-row report; an invalidation made inside the document's own layout (the controller's completion work) still gets its pass. There is no periodic viewport watchdog, lazy-stack rebuild escalation, per-row scroll marker or SwiftUI item scrolling. Removing or prepending rows preserves a retained visible neighbour, and user input cancels pending programmatic positioning. Tool-detail disclosure and per-file source/diff choices live with the transcript, survive host recycling and content revisions, and expire when their rows leave the conversation.
- **Reply placeholder.** A prompt sent from Chat that starts a turn arms it (not a steered message, not with Reduce Motion or in the radio log); once 0.5 s have passed and the agent acknowledged the prompt while still working, the transcript's last row is an empty assistant bubble (`ChatSession.pendingReply`, a row with `placeholder` set). One light moves at a time: from the send the composer's border stays neutral (`replyHaloOwnsActivity`), the bubble shows the footer's activity (◆ and orbit, label, time; `ChatReplyPlaceholderStatus`) where its first word will be, with a stop on hover, while the footer's dims to a still ◆ and label, its time blank in its slot and its details still a click away (`replyShowsStatus`), and the composer's lap goes around its outline (`ChatReplyHaloView`, one overlay above the rows of the transcript document, framed on the bubble's rows). Scrolled out of view (the transcript document reports it from the rows' frames, within its insets, as `ChatSession.replyBubbleInView`), the bubble hands the activity back: the footer is at full strength and the composer's border laps. The new turn's first reply, tool step or narration takes the placeholder's row ID, so it fills the same row without a second entrance; a reasoning summary, its own disclosure row, shows above the placeholder instead. Then the footer's activity comes back to full strength and the light and its accent edge fade into the bubble's outline over 1.2 s (`ChatSession.landedReply`), after which the composer's border fades its working light back in (0.4 s) for the rest of the turn. In Low Power Mode neither light laps (`MotionRate.decorates`, which also stills the label's shimmer, the Thinking row's sweep, the radar and a connecting tab's pulse): the steady accent edges carry it. Content of an earlier turn never takes it over, content before it shows disarms it, and a turn that ends, a failed prompt or a reset removes it.
- **Thinking fold.** Once a turn ends on a reply, its Claude or Pi thinking (`ChatItem.isNarration`) folds with its tools into one collapsed step group of `Think` rows, whose header counts them apart ("4 steps, 1 thought"; `ChatSession.foldsThinking`, off under XCTest as `readingHoldEnabled` is). A turn stopped or failed before a reply keeps its thinking. History is folded as it is read; a turn seen ending here is held in `heldThinkingTurns` for `thinkingFoldDelay` (1.2 s), then `attemptThinkingFold` decides: a followed, presented view animates; Reduce Motion and Low Power Mode swap at once, as does a turn out of the reader's view. A reader scrolled up inside the turn holds it until they return to the end, and a step or group they opened holds it until the next turn, which also lets any other held turn go. The merged group has its own identity and starts collapsed, so an opened group does not open the whole list. The animation (`ChatTranscriptDocument.prepareThinkingFold`, 0.28 s) measures nothing per frame: before the rows change it snapshots the folded rows the clip shows and records where the first of them and the reply stand; the row swap happens in one pass; then rows above the new group and rows from it down move back to their places by their own distances (the upper one clamped to a viewport, so 3 thoughts and 200 travel alike; the lower one zero while the window stays full, nonzero when the fold makes the chat shorter than the window, which is laid out from the top), the snapshot clipped between them and fading while the group's header fades in.
- **Typed reveal.** A reply that streams into the live turn while its chat shows (Codex's and Pi's deltas, `ChatTypingReveals.streamingAgents`), and thinking shown in the thread that streams in the same way (Pi's `thinking_delta`, in its muted color), types out instead of landing in bursts: a per-message clock (`ChatTypingClock`, pure and given its times) keeps the reveal about 0.3 s behind what has arrived, at least 28 characters a second while text waits, eased so its speed never jumps, pausing after `,;:` and `.!?` and at a new block, and catching up faster once the stream ends; a 2-point accent caret follows the last character shown in a text block (solid while typing, blinking while caught up, fading once complete; code, tables and rules show none; a reply whose first words are all a construct still arriving shows the caret alone on a line, never an empty bubble). Claude Code posts whole messages (`ChatTypingReveals.postingAgents`): one that arrives while its chat shows and would type within 2 s (`postedLimit`) types out as if it streamed in at 160 characters a second (`ChatTypingReveal.postedRate`, pauses counted, with the clock's 0.3 s as a head start), through the same clock and caret, even once its turn has ended; a longer one shows at once. A reveal that rested (caught up, faded, past its blink) takes up what arrives next from where it shows, and a transcript held off screen keeps its live turn with its rows, so a reply typing when the window left goes on when it is back. The reveal cuts the rendered text, never the source: what can show is the arrived text up to anything half-arrived (an open code span, emphasis, link (parentheses in its URL balanced) or autolink, a trailing backslash, a task's unfinished box, a trailing line that may still become a list item, heading, fence or table row; `ChatTypingLayout.stableEnd`), code shows by line and tables by row, and the rest of the word being typed (up to 200 characters: paths and URLs too) is laid out undrawn, and unread by VoiceOver, so it never jumps lines; the message grows a line at a time and following the end follows what is shown. Everything else shows at once: complete messages, other turns, history, Claude Code's thinking (posted whole), a reply first drawn when the chat opens mid-stream (it types from there), Claude Code's longer posts and any of its replies once typed (its rows are never marked complete, so the store is told the agent posts, `ChatTypingReveals.posts`, and leaves no caret on the newest one waiting for a stream), a posted reply shown again after its row left (scrolled away, its tab switched: whole, with no caret), Reduce Motion, and every test run (`ChatTypingReveals.enabled` is off under `DISPATCH_TESTING` and XCTest, though on in an iPhone app XCUITest launches, so recorded waits on a reply's text never depend on display time; the reveal's own tests turn it on and step its clock by hand). The state lives beside the session's view state (`ChatSession.typingReveals`, `MobileChatSession.typing`), never in the model or on disk, and one display link runs only while a shown reveal types or fades (on the Mac at the motion policy's rate, `MotionRate.range`: the screen's own on the adapter with Dispatch in front, 60 on battery or behind another app, where each frame lays out and draws the live row again; 30 in Low Power Mode) or blinks (at most 6 s, at about 10 frames a second), and stops with its session: an idle chat runs nothing. On the Mac that link is the transcript view's own (`NSView.displayLink`, handed over by `ChatTranscriptDocument` while it is in a window: `ChatTypingReveals.shows(in:)`), which AppKit keeps on the display its window is on and pauses while the window is off screen, and it is made again when the window changes screens or the screens wake; with no view in a window it steps on a timer. It is never a screen's (`NSScreen.displayLink`): such a link belongs to one display id and, once that id is gone (a monitor that drops out or returns from sleep under another), stays silent while reporting itself unpaused, and a store that kept it froze every later reply at its first character. The thinking fold's link is the document's own for the same reason. A text view rebuilt as it types loses a selection made in the typing block.
- **Message actions.** As the iPhone's long press and tap do: right-clicking a message's text puts Copy Message (its Markdown), Reply (an agent's message: quoted above the draft, the composer focused) and Info above the text view's own items (`ChatMessageMenu`, set by the row and read by `ChatSelectableText`; a selection keeps the text's own Copy). Info opens at the point clicked (an AppKit popover: a reply can be taller than the window); clicking a message's time opens the same details there. The details follow the phone's M1 (`ChatMessageDetailsView`): who and when with Copy, Reply and Show in Terminal, the message raw, the turn's outcome and times, its changes, the conversation's tokens and model, and its steps folded as the phone folds them (`ChatTurnSteps.swift`, shared); the exact times, identities and helper record wait closed under Record. Before macOS 26 messages are SwiftUI text, whose menu has Copy Message and Reply; Info opens from the time.
- **Terminal menu.** Right-click on a terminal (or Control-click) opens its menu (`TerminalView.contextMenu`), unless the program reads the mouse, which then gets the click: Copy, Paste, Select All, Open Link and Copy Link for a web link under the pointer, Clear Screen, Split Right and Split Down, then the modes the tab's switch offers (Terminal, Chat, Files, Review, Commits; `ModeSwitchMenuItem.items`, only those it can show). Clear Screen (⌘K) is disabled while a full-screen program shows (the alternate screen, which the engine leaves alone) and in a tmux or herdr tab, whose history is the server's (`TerminalView.canClearScreen`). A selection goes to the app menu's Services. One window: its close button and Window › Close Window and Quit (⌥⌘W) detach every space and quit, after the close confirmation.
- **Delivery.** After async work or reconnect, a submission revalidates its destination. Uncertain delivery is never retried automatically.
- **Held queues live on the host.** A Claude Code or Pi queue is the host's queue store (`helper/core/src/dispatch/store.rs`): one private file per conversation that every helper of the account shares, changed only by checked replaces, so what the host accepted survives the helper and every client sees one queue. Any helper bound to the agent sends the head item once a claim on it lands in the file; a claim whose helper is gone becomes an uncertain item. A helper that exits with sendable items starts the queue drainer (`helper/core/src/drain.rs`), a client of an ordinary helper that keeps those chats open until nothing is left to send. Chat operations are not serialized per session (`ChatOperations.run` starts a task per call, and a helper call can suspend before writing its frame), so requests from separate tasks reach the helper in any order: a row is marked pending when its upload is scheduled and re-checked right before the call, and Stop waits for an upload already on its way (`ChatSession.upload`) so the helper stops what it was just given instead of receiving it after the stop. A reopened chat hears of a stored queue only when it holds something, so a Mac still showing host rows (it was away while the host sent them) reads `queue.list` once the chat's history arrives, and again after any queue change the host refused as `expired` (`refreshHelperQueue`).
- **Terminal input order.** A tab's input to its helper is pipelined: calls go out in typing order without waiting for earlier replies, and input that queues meanwhile joins into one call (`HelperInputQueue`). Nothing overtakes the attach confirmation, a control client on the PTY, or checked keys, and a failure is reported late but never retried. Herdr wheel steps made while one is in flight join into the next `terminals.scroll`.
- **Agent requests.** Chat attaches only after discovery establishes process and conversation ownership. Approvals and question replies belong to a live request and never migrate with presentation state. Losing verification pauses input but keeps history and drafts.
- **Composer footer.** One row with everything in words, or one row with every optional item folded at once (`ChatView.FooterDensity`): Send without its keycap, no ⌘/ chip (the shortcut still opens its sheet), effort as its meter, the activity as orbit and time, drafts as an icon and count (`ChatDraftControls`; in words they are chips while their labels are short, else a `drafts N` menu), and the model name capped and truncated in the middle. Only a pane too narrow for that takes two rows, with the same folded items: the status on a strip that scrolls, Stop and its hint beside it, the drafts and actions below. Nothing comes back as the footer narrows; each folded item keeps its help and shortcut.
- **Model and effort picker.** When an agent's models are nothing but the rungs of one known family (haiku, sonnet, opus, fable; luna, terra, sol, astra), its security model (mythos, daybreak-blue) optional, the popover is two tracks instead of two lists (`ChatModelLadder`, the rule and the only model knowledge in the app, shared with the iPhone; `ChatModelPicker`'s tracks; `ChatModelControls`). Codex lists older generations beside the current one, so in its family only each model's newest is a rung. Anything else keeps the lists: an unknown model, two families, in Claude's family two versions or a `[1m]` variant of one, a current model off the ladder (an older Codex generation too, which is how to reach one). A stop on a track is a family or an effort level, weakest first, the levels being every one any model of the family is known to have, so a stop keeps its place; a level the shown model lacks is hatched. A click sends at once; a drag only on release, to the nearest stop the model has; ← → move the thumb at once and send after 0.6 s without a key. A change is one `chat.settings.set` with the model and the effort together (a model without the level brings the effort down, and the header says so until the popover closes), one at a time, the latest target winning; the thumb is translucent until the `chat.state` readback names it, and goes where the readback says if that names something else. The popover stays open after a change; closing it with a change waiting or on its way lets that finish first. The security model is no stop but a switch under the tracks, which returns to the last rung this chat used (`ChatSession.lastModelRung`), and the composer footer puts a shield before its name. Beside Codex's switch a Daybreak button runs `/daybreak` ([integrations](integrations.md)); choosing a model never does.
- **Attachments.** A file the user picks (paperclip or ⇧⌘A), drops anywhere on the chat's pane, or pastes (image data, Finder files) is read once, in the app, converted by `ChatAttachmentImage` and uploaded to the conversation's helper (`attachments.put`); messages and queue items name the host copy by path, never the original, so an agent never opens a file in the user's protected folders and an SSH host gets its own copy. Only helpers that accepted the `chat.attachments` hello feature are offered it, and never for commands, side conversations (`/btw` and `/side` refuse a draft with attachments) or queued edits (refused while the draft's uploads run). A photo's GPS, Exif, IPTC and camera metadata never leave the Mac (`ChatAttachmentImage.withoutMetadata`; orientation kept). Uploads in flight are `ChatSession` state only and belong to the draft they were started for, which takes the stored copy wherever the user switched meanwhile; `attachments.put` goes to the host's helper, not the chat's subscription, so a reopened chat does not drop it. The draft keeps what the host stored (with a small JPEG thumbnail); thumbnails read back from a host (`ChatAttachmentThumbnails`, `attachments.read`) stay in memory, and Quick Look reads a private copy in the app's temporary folder, removed when the panel closes, by the next preview, or at quit. A files view's rows dropped on the composer stay text: their quoted host paths. While files or images are dragged over the pane the composer grows to its top (`ChatComposerDropWell`): AppKit hands the drag to the composer's text view or, elsewhere in the pane, SwiftUI's drop, and the drag counts as over the pane while either has it (`ChatSession.attachmentDrag`), so the well does not drop between them; it shows the files as chips, the remote host a chat uploads them to, or that they would pass a message's limit. A files view's rows and text raise nothing. Delivery per agent is in [integrations](integrations.md).
- **Files mode's layout.** The files tabs (Files, Review, Commits) are switched from the strip's mode button, whose glyph names the one shown (`ModeSwitchState.glyph`: the folder, Review's clipboard, Commits' clock), from its menu, and with ⌃⌘1–3. A click on the button opens that menu in every mode (Terminal, Chat, Files, Review, Commits, the shown one checked; a hold or a right-click too), as the phone's tap does; ⇧⌘C and ⇧⌘F still switch at once, and VoiceOver's press takes one step; the files header leads with the tab's name and has no tabs of its own, and the review's comment count rides on Create Review (Review's and Commits' headers). Where git cannot run (not installed on the host, left out of its grant, refusing the folder as for dubious ownership) Review and Commits still open and say why; a status or log that fails after the repository is found shows git's error with Try Again in place of a spinner, and status reads back off a tick more after each failure, to about a minute (⌘R asks at once). Each tab's list and detail (the preview, a change's diff, a commit) take their places by a rule (`FilesView.shape`): in a space of four panes or more (2 × 2, 3 × 2, 4 × 2), one view at a time whatever the pane's size, so the layout chosen decides and every display agrees; otherwise by the view's size, side by side from 900 pt wide, narrower and at least 560 pt tall the list (at its own height, at most 40%) over the detail, narrower and shorter one view. The header's Single view toggle (arrows drawn in and lit while one view shows, drawn out while both do, on every tab) and ⌥⌘P (View › Show One View / Show List and Detail) switch a tab between one view and both (`FilesSession.oneView`, kept with the tab's view), in every layout, wherever both fit at all (`FilesView.fitsBoth`: 560 pt wide or 400 pt tall; smaller, one view and no button); both in a pane under 900 pt stack from 400 pt tall, else sit side by side at their minima. On one view (one column), where a row chosen shows its detail in the list's place (`FilesSession.drilled`; Review opens on the selected change's diff), the header's name becomes a button back to the list (as esc does; it keeps the name's width, "‹" taking its glyph's place, so nothing after it moves), what is open follows it, and ↑ ↓ step through the changes or commits; on Files the preview's header is the only row, led by that button (no search or views button). There a commit's summary and files take the whole pane, and a file opens its diff a level deeper, at the pane's full height (`FilesSession.drilledFile`): Back and esc return to the files, ↑ ↓ step through them. Under 900 pt diffs number their lines in one gutter, wrap until the wrap button says otherwise (`FilesSession.diffWrap` nil), name Diff and Source by glyph, and a commit's summary takes three lines with More.
- **Where a tab is.** Said as the phone's headers say it: the host by its name in its colour, then the folder's name (`build-box · app`). The Mac's hover cards lead with it (`SpaceHoverDetails.place`), the folder the tab's live one (`Workspace.liveTab`, as Files reads it), never a space's launch folder, and none for a plain SSH tab, whose folder this Mac does not know; the details line under it keeps the login, backend and full path. A folder whose name is the title or name beside it goes unsaid everywhere, the Mac's and the phone's alike (`SpaceHoverDetails.distinct`, `TabScreenHeader.distinct`): the host alone, never "api" under "api". Vertical tabs' heading says it for the space (a session's branch in the folder's place; a local space named for its folder has no line), the space's folder being where most of its tabs are (`SpaceTabPlace`); only a tab elsewhere gets a line under its title (its folder's name, unless its title already names it, or another host's name for a plain SSH tab), the full path in its help.
- **Files' previews off.** Settings › Features › Files › Disable file previews (`FilesSession.previews` false) keeps the pane, its toggle and ⌥⌘P; a file opened there shows its kind, size and date from its listing entry and Download…, and `FilePreviewLoader` reads none of it: no text, image, video or bytes, nor anything read before the setting changed. A folder still shows its summary. Wrap lines is on by default (Settings › Features › Files › Wrap lines; the preview's wrap button sets each tab).
- **Files' Markdown preview.** A Markdown file opens rendered (Settings › Features › Files › Render Markdown); the preview's eye button sets it for the tab (`FilesSession.previewRendered`, kept with the tab's view through a Restore and a relaunch), for every Markdown file the tab then shows. Rendered, it is a document rather than a message: `FileMarkdownView`, never `ChatMarkdown`, which it leaves alone and whose blocks, code blocks and tables it draws with. `FileMarkdownDocument` takes chat's blocks (`ChatMarkdownBlock.parse`) and flows them as a hard-wrapped file reads: a paragraph's lines into one (two trailing spaces or a backslash still break), an indented line into the list item above it, a quote's lines into one quote, four-space indents as code, YAML front matter as a `yaml` block. The parser drops blank lines, so a list item's second paragraph joins its first. `FileMarkdownStyle` sets it for reading: prose three points over Settings' size where chat's replies are one over, in the chat font (San Francisco where that is the code font), code blocks a point over chat's, in a centred column at most 36 em wide (about 80 characters a line); six sizes of heading, each with more space above it than under it. A heading with a section shows a chevron in the margin under the pointer, which folds everything up to the next heading of its level or above; a folded one keeps its chevron and a mark after its title. Folds are the tab's, by the file's path and the heading's level, title and order (`FilesSession.previewFolds`), so they hold while the file changes elsewhere and while the tab shows other files; they are never written anywhere, and the preview's find shows every section while it has a query. The header's outline button (rendered, a file with headings) lists them indented under the ones they belong to: one scrolls to its section and opens the folded ones around it (`FilesSession.reveal`), and Fold All leaves a heading that is alone at its level open, so a file's title still shows its sections.
- **Files' previews and diffs.** A preview reads its file once; when the listing (the 2 s poll, ⌘R) shows the previewed file at another size or time, it reads it again into a state of its own and shows that in place (`FilePreviewLoader.refresh`), so the header's size and time and the text follow the file without blanking. Text that is not UTF-8 shows as text when its encoding can be told (UTF-16 by its byte-order mark, Latin-1 for 8-bit text without controls), its encoding named in the header; other bytes without a NUL show as hex marked "Not UTF-8 text". A text preview's header copies the whole file, a diff's the whole diff, and a hunk's right click copies the hunk. ⌘F finds in a diff while it has the keyboard (`FilesSession.diffFocused`), else filters the list; Files' filter is a name filter of the folder shown ("Filter"). In Commits, ⏎ or → in a commit's files gives the file's diff the keyboard and esc gives it back; the git lists also page (Page Up, Page Down) and go to their ends (Home, End). A signature reads "Verified" (a certified key), "Signed · key not certified" (an outline seal) or "Checking…"; the graph's lanes other than the checked-out branch's cycle through colours told apart with any colour vision, and a "+N" of folded lanes says what it is in its help.
- **Files' copy and download.** A files view's rows menu has Copy (⌘C: the files, which Finder pastes; a host's rows are fetched first, `FilesDragController.copyToClipboard`), Copy Path (⌥⌘C), Copy scp Command (a host's rows, by the destination the tab's ssh started with: `FilesScpCommand`), Download… (also in a preview too large to show or not shown as text) and, for this Mac's rows, Reveal in Finder; there is no editor, and only cd Here (the crumbs' menu, a folder's preview) types into the tab's terminal, at a prompt only (`FilesTerminalCommand`; why it did not shows in the files header). Files copies and never moves: rows dragged within their own list copy only with ⌥ (a plain drag there, a move in Finder, is refused and the list says so); a copy that finishes selects what arrived under its own name. A finished copy's row stays until its Files list has shown for a few seconds, and closing its tab or quitting asks first while a copy runs. Both fetch through `FileTransferEngine` into a private folder, as a drag out does, so each shows as a transfer row (Copy's "to Clipboard"), and the app moves a download where the panel chose (docs/security.md, Files copied or downloaded).
- **Commits' filter.** The header's filter button (lit while anything but the checked-out branch's whole history shows) and the footer's name of it open one menu (`GitLogFilterMenu`): the current branch, all branches, another local or remote branch (`FilesSession.logRef`, its history read-only from that ref's commit: nothing is checked out; a deleted one gives way to HEAD's), and Only tagged commits (`logTagged`: `log --simplify-by-decoration --decorate-refs=refs/tags`, the undecorated root git adds left out by `GitLogPages`), with any of them. Over another branch or the tagged commits the uncommitted row gives way, and the graph draws dots only, as for a search. The choice is kept with the tab's view; the header's branch stays the checked-out one.
- **Reviews.** The Review tab (internally still `changes`, ids `git-changes-*`) is always a tab of its own. Its line comments are for coding agents, and so are a commit's in Commits (`ReviewComment.commit`, its hash): one review per repository holds both, and Create Review (in both tabs' headers) sends them together, each commit comment named by its short hash. Until the first comment the button is quiet (and gives way in a view under 900 pt), its help and popover say how to comment, a line over the diff's rows says so too, and the keyboard's row shows a faint +. Create Review re-reads every commented file (a commit's lines are looked for in the file as it is now; its removed lines keep their numbers); then Copy Review copies the text and keeps the comments, the bar offering Clear Comments (with Undo), or Send hands it to an agent through its composer and clears them, the bar offering Restore Comments (the agent keeps what it got). The bar's note goes six seconds after the review went, by the clock. In the overall comment ⏎ adds a line and ⌘⏎ sends (or copies). A new comment keeps its text only on its own file: starting one on another file sets the first aside (`FilesSession.reviewSetAside`), and Create Review lists every comment not saved, to Keep or Discard, never sending one unless kept; esc or Cancel on a new comment with text asks before discarding it. Comments persist per repository (`ReviewRepository`, `reviews.json`; the header says when they cannot be read or saved) and expire after 30 days unchanged (`ReviewRepository.expiry`).
- **Persistence.** Settings, workspace restoration, saved terminal output, drafts and Review comments belong to `SettingsStore`, `HostSessionStore`, `TerminalHistoryStore`, `ChatDraftRepository`, and `ReviewRepository`; grants, host identities, consent choices and window state also persist in UserDefaults ([stored data](security.md#data-stored-on-your-mac)). Dispatch never restores shell processes. Sensitive files go through `PrivateFile` (owner-only, atomic). Agent histories and tmux/herdr sessions belong to those tools.
- **Pre-release settings.** Only current preference keys are read. Removed sidebar, appearance, contrast, Option-key, prefix-key, multiplexer and dictation settings take today's defaults; they are not translated. Graphite and Lavender are no longer desktop app themes (the iPhone keeps its own), and an unknown theme resets only that choice. A missing light terminal scheme uses its own default. Multiplexer launching tabs always close after attachment (tests may retain them in memory); `closeLaunching` is no longer persisted. The current clipboard and SSH-consent storage keys stay unchanged so explicit permission choices survive. Reviews and credential protection retain their data migrations.
- **Diagnostics.** `ChatViewportTrace` is opt-in, bounded, and never records conversation text, host/user details, paths, or original row IDs.
- **Chat composers.** The main, `/btw`, and `/side` composers (and the Review tab's comment editors) use `ChatCaretTextView`/`ChatEditorTextView`. Never revert one to a SwiftUI `TextField`: its native caret rendering made Chat slow on 120 Hz Adaptive-refresh displays (external displays and ProMotion MacBooks, especially in full screen). `ChatSideComposerTests` guards caret, IME, focus, and drafts.
- **Composer keys.** Return sends in compact mode; Option-Return and Shift-Return insert a newline without changing editor mode. Command-Return and Control-Return send from either mode. Command-Option-Return takes the alternate send action: steer by default, or queue when Settings makes ordinary send steer. Holding Command and Option together shows that alternate action on the send button and clicking performs it. For a queued message selected with the keyboard (Up from an empty compact draft) and an empty compact draft, Command-Option-Return sends that row now, E edits it and Command-Delete deletes it; a row under the pointer shows its buttons but takes no keys. Option-Return still inserts a newline. With the command list open, Return accepts the highlighted command as Tab does, unless the draft already is that command. Editor mode (Command-E or a multiline paste) makes Return insert newlines, except a one-line agent command still submits. Escape first clears a queue selection or leaves a queued message's edit (its editor mode, then the edit); otherwise, while the agent works, two presses within a second stop it, in editor mode too, and while it is idle Escape leaves editor mode. The Stop button stops immediately. Shift-Command-Return (Allow Once) and Shift-Command-Delete (Deny) answer the newest pending permission card, or an open side conversation's, from anywhere in the chat's pane (Chat menu); a question form takes the keys while it shows: Return is Next and then Send Answers, Escape is Skip while nothing is answered. The Chat menu lists these and the composer's other actions with their keys. Double Control-D in an empty compact draft closes the tab and quits the agent, or shows Terminal while it works. Both keyboard behaviors are fixed; their removed saved settings are ignored.
- **Engine.** The terminal is the Swift terminal (`Vendor/Term`, ported from Ghostty) behind [`TerminalBackend`](../Dispatch/Terminal/TerminalBackend.swift). It reads a Ghostty-syntax config, bundles Ghostty's shell integration (without its `cursor` feature, whose blinking bar at every prompt would override Settings' cursor) and themes (`Vendor/Term/Resources`), and draws with the contrast shader in [`Shaders.swift`](../Vendor/Term/Sources/TermApple/Shaders.swift).
- **Shutdown.** Save the remote workspace, unmount native views, stop coordinators, destroy surfaces, release the terminal engine, then await SSH/launcher cleanup.
- **Quit runs in two passes.** After `applicationShouldTerminate` answers `.terminateLater`, AppKit waits in a nested event loop that runs no `DispatchQueue.main.async` work and no main-actor task continuations (timers in `.common` modes and posted events do run), so a reply that depends on main-actor work never comes. A user's quit therefore answers `.terminateCancel`, finishes the cleanup on the outer loop and calls `terminate` again, which answers `.terminateNow`; a logout or shutdown (an Apple event with `keyAEQuitReason`) saves the session and is granted at once. Never await main-actor work from inside an AppKit nested loop (modal sessions behave the same).
- **Render threads keep their run loop.** A terminal's render thread (`Frames`) runs its own run loop, kept alive by a port: AppKit invalidates a view's display link when the view leaves its window, and a run loop with no sources left returns, ending the thread and leaving the tab undrawn while its shell keeps running.
- **Terminal output is paced; input is not.** A change from output alone (a program printing, a spinner, an agent's status line) draws at the display's rate on the adapter with Dispatch in front and at most 30 frames a second otherwise (`MotionRate.terminalOutput`: on battery, behind another app, in Low Power Mode), its link asking the display for that rate; the host's own actions (`Session.pump()`: keys, scrolling, resizing, selection), and output for 0.25 s after one (the echo, the program's answer), draw at the next refresh (`FrameDemand`). Pumps that output brings (host messages, a changed scrollbar, the cursor's blink) count as output.
- **One state per frame.** A change the user sees lands in one main-actor turn: two layout commits split across turns or tasks, or a pending round trip, let the window draw the state in between, and even one frame of it is a visible flicker. Tests sample state after each changing turn rather than polling for the final state (`TmuxWalkthrough.sidebarShown()`).
- **Animations are scoped.** `.animation(_:value:)` sits on the smallest subtree, keyed to a value that changes only with what it animates: on a container it also animates its children's changes (a font size set in the same update), and an animation around `glassEffect` animates the layout of everything inside the glass. A blanket `.transaction { $0.animation = nil }` kills every animation inside; scope it with `.transaction(value:)`. The model and coordinators use no `withAnimation`, so a `.transition` whose condition flips there runs only if an ancestor's `.animation(value:)` or the transition's own `.animation(…)` covers it, and a child inserted together with its parent never runs its own.
- **Typography.** Every text font draws at Source Code Pro's lowercase height at its size: the median outline height of "acemnorsuvwxz", measured at run time by [`TerminalFontScale`](../Dispatch/Terminal/TerminalFontScale.swift) for terminal fonts, chat's faces (`ChatFont.sizeScale`) and the interface's San Francisco (`AppFont.systemScale`, SF Rounded); `PlanOneTests` holds them to it and `swift scripts/measure-fonts.swift [size]` prints every role. Lines too: from macOS 26 chat's prose (`ChatTypography.lineHeight(for:)`, TextKit's fixed line height) and interface text (`.font(typography, .role)`, SwiftUI's `lineHeight`) are set on Source Code Pro's line at their size (`AppFont.lineHeight`), so switching fonts moves no line or row; that line height is an environment value, so window, pane and sidebar roots set a plain font and leave it to the views that set a role. Widths stay each face's design: text that changes in place reserves its widest variant (`ReservedText`), and SF Symbols beside text take its role's size (`AppTypography.symbol`). Sizes are offsets from Settings' font size: terminal and code at it, chat prose one point over, interface text in `AppTypography.Role` (title +0.5, label −0.5, body −1.5, caption −2.5, micro −3; only display headings pick their own). Settings draws at a fixed 13.5, so its controls stay put while the slider moves. The interface font is San Francisco by default, or Same as code: the terminal font (`InterfaceFontStore.codeFamily`) at the size the terminal draws it, its nearest semibold where it has none (Bold, or Latin Modern Mono Light's), Source Code Pro once the family is gone; a saved Source Code Pro, the choice before it, reads as Same as code. Text that is code (paths, commands, color values) is the terminal font whichever, drawn as Same as code (`AppFont.code`); only onboarding's pictures, drawn to a fixed size, keep Source Code Pro (`AppFont.sourceCodePro`). Activity marks are SF Symbols (`ActivityMark`), never characters: San Francisco lacks ◌ ◆ ◐ and would take them from mismatched fallback fonts.
