# Architecture

Each rule here guards against lost sessions, misdelivered input, or leaked data. Build and test mechanics are in the [README](../README.md#run) and [test/README.md](../test/README.md); tmux, herdr, SSH, and agent lifecycles are in [integrations](integrations.md).

| Owner | Owns |
| --- | --- |
| [AppDelegate](../Dispatch/AppDelegate.swift) | Wiring, restoration, shutdown order. |
| [Workspace](../Dispatch/Workspace.swift) | Spaces, panes, tabs, selection, host placement. Related mutations publish together through `updateLayout`. |
| [TerminalRuntime](../Dispatch/Terminal/TerminalRuntime.swift) | The terminal engine and its surfaces, keyed by stable UUID. |
| [Hosts](../Dispatch/Hosts/) | Presentation identity, kept separate from live process ownership and connection recipes. |
| [SSH](../Dispatch/SSH/) | Enhanced-connection authentication and per-connection feature grants. |
| [Helper](../Dispatch/Helper/) / [Herdr](../Dispatch/Herdr/), over the helper's [tmux](../helper/multiplexers/tmux/) and [herdr](../helper/multiplexers/herdr/) crates | Mapping server-owned sessions into native spaces and tabs. |
| [Chat](../Dispatch/Chat/) | Agent discovery, per-surface sessions, drafts, submissions, approvals. |
| [Views](../Dispatch/Views/) | Presentation only. Views never own shell lifetime. |

## Invariants

- **Threading.** Workspace and UI coordinators are `@MainActor`. Blocking I/O, process inspection, and heavy parsing run on transport actors or background workers that report back to the owning coordinator.
- **Identity.** Host changes, reorders, splits, and Terminal↔Chat switches preserve surface and conversation identity. Presentation changes never relaunch a shell or acquire input authority.
- **Server-owned sessions.** Detaching a native view from tmux/herdr is not terminating server work. Backend snapshots reconcile existing presentation identities in place.
- **Remote trust.** Host grouping is presentation, not a permission boundary: grouped aliases can have different grants. Remote operations carry authenticated connection/process identities and generations, and a remote PID is never a local PID. Agent hooks on a remote connection need that connection's grant. Ordinary SSH works without the helper.
- **Screens.** The Mac never publishes screens (`terminals.publish`) for the tmux and herdr terminals of a helper whose hello accepted `screens.host`: that helper reads them from the multiplexer, and one publication would turn its host reads off for that terminal. It publishes native terminals and SSH logins a helper observes in a tab, and everything to a helper without the feature (`HelperWorkspace.publishes`); a terminal that publishes to nobody reads no screen until that changes (`TerminalView.wakeScreens`).
- **Hidden terminals.** A hidden terminal's output is held on the host, never dropped silently: showing it again restores the screen. A chat tab whose terminal is not on screen may stop its subscription's output (`terminals.follow` false, helpers that accepted the feature, tmux and herdr only); following again gets that subscription alone a whole repaint before any later output, and input, exits, chat records and the host's screen reads go on meanwhile. Plain terminal tabs always follow. While output to the app is backed up the helper still reads and runs its requests (`requests.backlog`: keystrokes, cancels, `terminals.follow false`, pings; up to 256 waiting replies or 1 MiB), so a flood in a visible pane delays only the replies, not what the requests do. An output window (`terminals.window`: at most 256 KiB of unacknowledged terminal output per client, acknowledged per attach subscription by `HelperOutputWindow` once handed to the terminal (batched while streaming, flushed when quiet), the multiplexers paused past it) exists but is off by default (`HelperSession.outputWindow`).
- **Off-screen chats.** While a chat's main window is off screen (ordered out, or the app hidden; not minimized), its transcript keeps the rows it showed when the window left (`ChatSession.holdTranscript`): records, unread state, approvals and notifications go on in the model, but no row is laid out or mounted for them. `MainWindow` posts `willShow` before it is ordered in or its app unhides; the transcript applies what it held there, and the window lays it out, draws and commits it before it is ordered in, so no stale frame shows. A covered (occluded) window keeps updating: the window server shows it again before the app hears it is visible.
- **Delivery.** After async work or reconnect, a submission revalidates its destination. Uncertain delivery is never retried automatically.
- **Held queues live on the host.** A Claude Code or Pi queue is the host's queue store (`helper/core/src/dispatch/store.rs`): one private file per conversation that every helper of the account shares, changed only by checked replaces, so what the host accepted survives the helper and every client sees one queue. Any helper bound to the agent sends the head item once a claim on it lands in the file; a claim whose helper is gone becomes an uncertain item. A helper that exits with sendable items starts the queue drainer (`helper/core/src/drain.rs`), a client of an ordinary helper that keeps those chats open until nothing is left to send.
- **Terminal input order.** A tab's input to its helper is pipelined: calls go out in typing order without waiting for earlier replies, and input that queues meanwhile joins into one call (`HelperInputQueue`). Nothing overtakes the attach confirmation, a control client on the PTY, or checked keys, and a failure is reported late but never retried. Herdr wheel steps made while one is in flight join into the next `terminals.scroll`.
- **Agent requests.** Chat attaches only after discovery establishes process and conversation ownership. Approvals and question replies belong to a live request and never migrate with presentation state. Losing verification pauses input but keeps history and drafts.
- **Attachments.** A file the user picks (paperclip or ⇧⌘A), drops on the composer or transcript, or pastes (image data, Finder files) is read once, in the app, converted by `ChatAttachmentImage` and uploaded to the conversation's helper (`attachments.put`); messages and queue items name the host copy by path, never the original, so an agent never opens a file in the user's protected folders and an SSH host gets its own copy. Only helpers that accepted the `chat.attachments` hello feature are offered it, and never for commands, side conversations (`/btw` and `/side` refuse a draft with attachments) or queued edits (refused while the draft's uploads run). A photo's GPS, Exif, IPTC and camera metadata never leave the Mac (`ChatAttachmentImage.withoutMetadata`; orientation kept). Uploads in flight are `ChatSession` state only and belong to the draft they were started for, which takes the stored copy wherever the user switched meanwhile; `attachments.put` goes to the host's helper, not the chat's subscription, so a reopened chat does not drop it. The draft keeps what the host stored (with a small JPEG thumbnail); thumbnails read back from a host (`ChatAttachmentThumbnails`, `attachments.read`) stay in memory, and Quick Look reads a private copy in the app's temporary folder, removed when the panel closes, by the next preview, or at quit. A files view's rows dropped on the composer stay text: their quoted host paths. Delivery per agent is in [integrations](integrations.md).
- **Persistence.** Dispatch saves only what `SettingsStore`, `HostSessionStore`, `TerminalHistoryStore`, `ChatDraftRepository`, and `ReviewRepository` (the Review tab's comments) save; it never restores shell processes. Sensitive files go through `PrivateFile` (owner-only, atomic). Agent histories and tmux/herdr sessions belong to those tools.
- **Diagnostics.** `ChatViewportTrace` is opt-in, bounded, and never records conversation text, host/user details, paths, or original row IDs.
- **Chat composers.** The main, `/btw`, and `/side` composers (and the Review tab's comment editors) use `ChatCaretTextView`/`ChatEditorTextView`. Never revert one to a SwiftUI `TextField`: its native caret rendering made Chat slow on 120 Hz Adaptive-refresh displays (external displays and ProMotion MacBooks, especially in full screen). `ChatSideComposerTests` guards caret, IME, focus, and drafts.
- **Engine.** The terminal is the Swift terminal (`Vendor/Term`, ported from Ghostty) behind [`TerminalBackend`](../Dispatch/Terminal/TerminalBackend.swift). It reads a Ghostty-syntax config, bundles Ghostty's shell integration and themes (`Vendor/Term/Resources`), and draws with the contrast shader in [`Shaders.swift`](../Vendor/Term/Sources/TermApple/Shaders.swift).
- **Shutdown.** Save the remote workspace, unmount native views, stop coordinators, destroy surfaces, release the terminal engine, then await SSH/launcher cleanup.
